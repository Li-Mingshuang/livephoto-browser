# LivePhoto 浏览器

### Windows 上最好用的 iPhone Live Photo 浏览器

把 iPhone 导出的 Live Photo 交回它该有的样子：**滚一下就到、点一下就活、有声音。**

> Windows 自带的「照片」和资源管理器都不把 Live Photo 当回事 —— 要么只给你一张静止的 HEIC，
> 要么把 `IMG_1234.HEIC` 和 `IMG_1234.MOV` 当成两个互不相干的文件。
> 而 Live Photo 之所以叫 Live，是因为按下它的时候照片会动。
>
> **这个工具只做一件事：在 Windows 上把 Live Photo 正确地、流畅地、好看地放出来。**

---

## 它有什么

### 📸 像个正经相册，而且只读

- **不导入、不建库、不复制**：选一个文件夹就是打开一个相册，关掉就走，一张照片都不动
- 17,159 个文件的目录，**257ms** 扫完（66,769 文件/秒）—— 因为只读目录元数据，从不打开文件内容
- 侧栏目录树（按子树计数、点击过滤）+ 日期分组 + 右侧时间轴

### 🎞️ Live Photo 是真正的 Live Photo

| 能力 | 做法 |
|---|---|
| **网格悬停即预览** | 鼠标停 0.4 秒，那格就静音循环动起来；滚走就停 |
| **点一下播放** | 全屏里点 `LIVE ▶` 或按 **空格**，带声音播一遍 |
| **切过去自动播放** | 滑到一张 Live Photo 就自动播，和 iOS 相册一样 |
| **零转码** | 直接把系统 HEVC 扩展解出的原始 MOV 交给播放器 —— **不转码、不生成预览缓存** |
| **配对正确** | 同目录同名主干配对；实测在真实库上 311 对全部命中 |

### ⚡ 快，而且快得有道理

| 环节 | 实测数字 |
|---|---|
| 扫描 17,159 个文件 | **257 ms** |
| 已缓存缩略图读取 | **14,896 张/秒** |
| 网格滚动（5000 格、真实照片） | **58.5 fps**，p50 = **16.7 ms**（跑满 60Hz vsync） |
| 7832 个资产同时存在时的 DOM 节点 | **54 个** |
| 全屏切换（已预加载） | p50 **35 ms** |

快的原因不是"优化得狠"，而是几处**设计上直接绕开了开销**：

1. **索引只碰元数据，绝不打开文件内容。** 这同时也是**安全性**：iCloud/OneDrive 的照片目录里
   大量文件是"云端占位"（数据不在本地），打开就可能是触发下载甚至直接报错。我们只读目录项，
   所以**整个库都在云上也能秒开网格**。
2. **只解你正在看的那一屏**，滚过就取消。实测：清空缓存后打开一个大目录，
   只生成了 111 张缩略图（正好是可见区）就停下了 —— 其余 7800 多个资产一个都没碰。
3. **多级图源，让"等待"从界面里消失**：网格层立刻顶上 → 全屏层算好无缝替换；
   已预加载的图**直接显示清晰图、根本不经过模糊的小图**。
4. **缓存是纯派生数据**：存在 `%LOCALAPPDATA%\LivePhoto\cache`，有 4GB 上限、按最旧优先淘汰，
   整个删掉只损失时间，不会丢任何照片。

### ⌨️ 操作

| 操作 | 作用 |
|---|---|
| 双击缩略图 | 打开全屏 |
| `←` `→` | 全屏切换上一张 / 下一张 |
| **空格** | 播放 / 停止 Live Photo |
| **滚轮**（全屏内） | 以光标为锚点缩放图片（1× ~ 8×） |
| 拖动（放大后） | 平移；双击复位 |
| `Ctrl` + 滚轮 | 缩放网格缩略图（80 ~ 320px） |
| `↑` `↓` `PgUp` `PgDn` `Home` `End` | 网格滚动 |
| `Esc` | 关闭全屏 |
| 侧栏目录 / 时间轴 | 过滤目录 / 拖动跳转月份 |

## 下载与运行

去 [Releases](../../releases) 下载 `LivePhotoBrowser.exe`，**双击即用**：

- 单文件 **4.5 MB**，不需要安装、不需要 Node、不需要 Vite
- 打开后填文件夹路径（或设环境变量 `LIVEPHOTO_OPEN` 直接进入）

```powershell
$env:LIVEPHOTO_OPEN="F:\DCIM"; .\LivePhotoBrowser.exe
```

### 环境要求

- Windows 10 1809+ / Windows 11
- **WebView2 运行时**（Win11 已内置）
- **HEIC / HEVC 解码**：即微软的 *HEIF 图像扩展* 与 *HEVC 视频扩展*。
  多数品牌机预装；缺失时 HEIC 缩略图与 Live Photo 播放不可用。

## 自己构建

```powershell
cd app; pnpm install; pnpm build                      # 前端 → app/dist
cd ..; cargo build --release -p app --features custom-protocol
# 产物：target/release/app.exe（约 4.5 MB）
```

> ⚠️ **`--features custom-protocol` 必须带。**
> `tauri` 的 build.rs 用 `let dev = !custom_protocol;` 判断 dev/prod ——
> 缺了它 release 二进制会去连 `devUrl`（localhost:1420），窗口白屏且**没有任何报错**。
> 用官方 CLI（`pnpm tauri build`）会自动带上。

开发模式（debug 加载 `devUrl`，必须同时起 Vite）：

```powershell
cd app; pnpm dev                       # 终端 1
$env:LIVEPHOTO_OPEN="F:\DCIM"; .\target\debug\app.exe   # 终端 2
```

## 技术栈与结构

**Rust 核心 + Tauri v2 + WebView2**。不打包 Chromium，不打包编解码器。

```
core/                 # 核心层，不依赖 Tauri（所以 bench 能秒级编译）
  files.rs            # 目录扫描：只读元数据 + 云占位识别
  pairing.rs          # Live Photo 三级配对
  movmeta.rs          # MOV box 解析：时长/编码/分辨率/still-image-time
  cache.rs            # 磁盘缓存 + LRU 淘汰
  thumbs.rs           # 缩略图工作池：常驻 STA 线程 + 优先级队列
  media/wic.rs        # WIC 图片解码
  media/mf.rs         # Media Foundation 视频抽帧
  src/bin/            # 各类 bench 与验收工具（可复跑所有性能结论）
app/                  # Tauri 应用：命令层 + 自定义协议 + 前端
docs/                 # 三份文档，分工明确
tools/                # 侦察与验证脚本
```

## 已知限制（说清楚比吹得响重要）

1. **HEIC 解码约 900ms/张，且几乎不能并行**（6 线程仅 1.4× 加速）——
   这是系统解码器的限制。所以首次浏览一个大库时缩略图会逐个填充；
   但**浏览从不被阻塞**（只解可见区），且填过一次就永久命中缓存。
2. **翻页速度上限约 2~4.7 张/秒**。翻得比这快时，底部胶片条会显示"正在准备"——
   这是物理限制，不是卡死。
3. **日期用的是文件修改时间**，不是 EXIF 拍摄时间。
4. **滚动没有惯性**（自己接管滚轮以绕开 WebView2 的一个问题，代价是失去原生惯性）。
5. **只读浏览**，v1 没有编辑 / 导出。
6. 目前交付的是绿色版单文件，**还没有安装包**（MSI/NSIS）。
